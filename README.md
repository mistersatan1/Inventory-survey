# 재고조사 (기념품숍 · 체험장)

휴대폰 하나로 창고 재고조사를 끝내는 웹앱입니다. 빌드·서버·외부 라이브러리가 없습니다.

- `index.html`을 **더블클릭**해서 열어도, **GitHub Pages**에 올려도 똑같이 동작합니다. (`css/`, `js/` 폴더가 `index.html` 옆에 같이 있어야 해요.)
- 글꼴(Pretendard)은 인터넷이 될 때만 불러오고, 안 되면 기기 기본 글꼴로 보여요.
- 데이터는 이 기기의 브라우저(IndexedDB)에 저장됩니다. 인터넷이 끊겨도 입력·저장이 됩니다.
- 기기를 바꾸거나 브라우저 데이터를 지우면 데이터가 사라지므로, **설정·백업** 메뉴에서 자주 백업하세요.

## GitHub Pages에 배포하기

1. GitHub에서 이 저장소를 엽니다.
2. `index.html`과 `css/`, `js/` 폴더가 저장소 맨 위(루트)에 있는지 확인합니다.
3. 저장소 상단 **Settings** → 왼쪽 메뉴 **Pages**로 갑니다.
4. **Build and deployment**의 **Source**를 `Deploy from a branch`로 고릅니다.
5. **Branch**에서 배포할 브랜치(예: `main`)와 폴더 `/ (root)`를 고르고 **Save**를 누릅니다.
6. 1~2분 뒤 같은 화면 위쪽에 나오는 주소(`https://<아이디>.github.io/<저장소이름>/`)로 접속합니다.
7. 휴대폰에서 그 주소를 열고, 브라우저 메뉴의 **홈 화면에 추가**를 누르면 앱처럼 쓸 수 있습니다.

> ⚠️ **주의: 백업 파일(`재고백업_*.json`)을 저장소에 올리지 마세요.**
> 백업 파일에는 품목 사진과 모든 재고 기록이 들어 있습니다. GitHub Pages용 저장소는 대부분 공개 저장소라서 누구나 내려받을 수 있습니다.
> 백업 파일은 휴대폰·PC·개인 클라우드 등 비공개 장소에 보관하세요.

## 여러 기기 같이 쓰기 (서버 없이)

백업 → **여러 기기 같이 쓰기** 카드에서:
1. 각 기기에서 **[백업 파일 보내기]**로 한 기기에 파일을 모읍니다 (카톡 ‘나에게 보내기’ 등).
2. 받은 기기에서 **[다른 기기 기록 합치기]**로 파일을 고르면, 이 기기 기록은 그대로 두고 새 기록만 더합니다. 같은 기록이 다르면 더 나중에 고친 쪽이 남고, 지운 기록은 지워진 채로 전해집니다.
3. 다 합친 기기에서 다시 보내 다른 기기도 합치면 모든 기기가 같아집니다.

같은 품목을 두 사람이 따로 세면 나중에 넣은 숫자만 남으니, 품목(카테고리)을 나눠서 세세요. 이 기능이 생기기 전 버전에서 만든 백업은 ‘고친 시각’이 없어서, 같은 기록이 다르면 이 기기 것을 남깁니다.

## 다른 기기로 옮기기

설정·백업 → **전체 데이터 백업(JSON) 다운로드** → 새 기기에서 같은 주소를 열고 → **백업 불러오기**.

## 화면 용어와 엑셀 용어

화면은 처음 쓰는 사람도 알 수 있는 말로, 엑셀(CSV) 파일은 기존 엑셀 양식의 말로 씁니다. 월말 정산 표에는 두 이름을 같이 적었습니다.

| 화면에 보이는 말 | 엑셀(CSV)의 말 | 뜻 |
| --- | --- | --- |
| 처음 있던 수 | 전월 재고 | 지난달 말에 창고에 있던 수 |
| 있어야 할 수 | 예상 재고 | 처음 있던 수 + 반입 − 반출 − 판매 |
| 센 수 | 실사 재고 | 직접 센 수 (박스 × 1박스 기준 + 낱개) |
| 차이 / 차이 난 까닭 | 오차 / 오차 사유 | 센 수 − 있어야 할 수 |
| 오늘 기록 남기기 | (중간점검) | 그날 센 결과를 날짜별로 한 장 남김. 숫자 자체는 넣는 즉시 저장됨 |
| 이번 달 마감하기 / 마감 풀기 | (월말 확정 / 해제) | 마감하면 그 달이 잠기고 센 수가 다음 달 처음 있던 수가 됨 |

**센 날짜:** 재고 세기 화면 오른쪽 위 ‘센 날짜’에서 날짜를 고를 수 있습니다. 종이에 적어 온 실사를 다음 날 PC로 옮길 때 쓰세요. 예: 12월 1일에 11월 30일 실사를 넣으려면 날짜를 11월 30일로 바꾸면 11월 기록으로 들어갑니다. 오늘이 아닌 날짜를 고르면 주황색 안내가 계속 보이고, 앞날은 고를 수 없으며, 앱을 다시 열면 오늘로 돌아옵니다.

**PC에서 빠르게 넣기:** PC 화면(가로 900px 이상)에서는 재고 세기가 엑셀 표처럼 한 줄씩 촘촘하게 보입니다(1200px 이상이면 ‘차이 난 까닭’도 같은 줄). 키보드만으로 넣을 수 있어요.
- `Enter` → 아래 품목의 같은 칸 (박스 기준이 없는 품목은 낱개 칸으로), `Shift+Enter` → 위 품목
- `Tab` → 옆 칸 (박스 → 낱개 → 판매 → 까닭)
- `/` → 품목 찾기 칸
- 계산식(처음 + 반입 − 반출 − 판매)은 결과 칸에 마우스를 올리면 보입니다.

**탭 여러 개:** 같은 PC에서 앱을 여러 탭으로 열어도 됩니다. 한 탭에서 저장하면 다른 탭이 바로 새 내용을 읽어 와서, 옛 내용으로 덮어쓰지 않습니다(입력 중인 칸이나 열린 창이 있으면 그걸 마친 뒤 반영).

**소수점 수량:** 흙처럼 한 포대를 나눠 쓰는 품목은 단위를 `포대`로 두고(1박스 기준은 비움) 0.3처럼 소수점으로 적습니다. 예: 1포대 반입, 이번 달 사용 0.3 → 있어야 할 수 0.7, 센 수 0.7 → 딱 맞아요. 소수점 아래 셋째 자리까지 계산하고, 휴대폰 키보드가 `0,7`처럼 쉼표를 넣어도 0.7로 읽습니다(`1,200`처럼 쉼표 뒤가 세 자리면 천 단위).

처음 쓰는 달에는 **재고 세기 화면의 [처음 있던 수 넣기]** 에서 품목별로 넣거나, 엑셀에서 품목명·수량을 붙여 넣어 한 번에 채울 수 있습니다.

월말 정산 화면 위쪽의 **마감 순서**가 할 일을 차례로 보여 줍니다: ① 모든 품목을 셌나요? → ② 차이 난 까닭을 적었나요? → ③ 이번 달 마감하기. 끝난 단계에는 ✓가 붙고, 아래 전체 표는 자세히 보거나 인쇄할 때 씁니다.

## 계산 규칙

| 항목 | 계산 |
| --- | --- |
| 실사 합계 | 박스 수량 × 1박스 기준 + 낱개 수량 |
| 예상 재고 | 전월 재고 + 반입 − 반출 − 판매(사용) |
| 오차 | 실사 재고 − 예상 재고 (마이너스는 부족) |
| 다음 달 전월 재고 | 이번 달 확정된 실사 재고 |

`node tests/calc.test.js`로 브라우저 없이 계산 규칙을 확인할 수 있습니다. 브라우저 개발자 도구 콘솔에서 `Calc.selfTest()`를 실행해도 엑셀 예시값(전월 0, 판매 393, 반출 252 → 예상 −645 / 실사 7857 → 오차 8502)으로 계산을 확인합니다. 설정·백업 화면의 **계산 테스트 실행** 버튼도 같은 일을 합니다.

## 파일 구조

| 파일 | 하는 일 |
| --- | --- |
| `index.html` | 화면 뼈대(윗줄·메뉴·본문 자리)와 파일 불러오는 순서 |
| `css/tokens.css` | 색·글자 크기·간격·모서리 값. **색을 바꿀 땐 여기만** 고치면 돼요 |
| `css/base.css` | 초기화, 윗줄(매장 전환), 아래/옆 메뉴, 전체 배치 |
| `css/components.css` | 버튼·입력칸·배지·표·모달·토스트 같은 공용 부품 |
| `css/pages.css` | 화면별 모양 (재고조사 화분 진행 표시, 월말 정산 표 등) |
| `css/print.css` | 월말 정산 인쇄용 (A4 가로) |
| `js/utils.js` | 공용 도구: 날짜·숫자 형식, 초성 검색, 아이콘 |
| `js/storage.js` | 데이터 저장 (IndexedDB → 안 되면 localStorage) |
| `js/inventory.js` | 재고 계산 규칙(`Calc`)과 데이터 캐시, 품목·월 계산 |
| `js/ui.js` | 모달 · 토스트 · 확인 창 |
| `js/pages/count.js` | 재고조사(중간점검) 화면 |
| `js/pages/mov.js` | 반출입 기록 화면 |
| `js/pages/stock.js` | 전체 재고 화면 |
| `js/pages/month.js` | 월말 정산 화면 (확정·CSV·인쇄) |
| `js/pages/manage.js` | 품목·카테고리·조사 묶음 관리 화면 |
| `js/pages/settings.js` | 설정·백업 화면 |
| `js/import.js` | 엑셀 붙여넣기로 품목·재고 한 번에 등록 |
| `js/merge.js` | 여러 기기 같이 쓰기: 다른 기기 백업 파일을 합치기 (더 최신 기록 우선, 지움 표시) |
| `js/order.js` | 주문할 것 목록 (추천 수량, 복사·공유·CSV) |
| `js/app.js` | 매장 전환·메뉴 이동, 첫 실행, 클릭·입력 연결, 앱 시작 |
| `tests/calc.test.js` | 계산 규칙 테스트 (`node tests/calc.test.js`) |
| `tests/number.test.js` | 숫자 입력 읽기 테스트: 소수점·쉼표 (`node tests/number.test.js`) |
| `tests/merge.test.js` | 다른 기기 기록 합치기 규칙 테스트 (`node tests/merge.test.js`) |

스크립트는 `<script src>` 순서대로 불러와 서로의 함수를 바로 씁니다(모듈 방식이 아니라서 더블클릭으로 열어도 동작). 새 화면을 만들면 `js/pages/`에 파일을 두고 `index.html`의 `js/app.js` 앞에 추가하세요.

## 디자인 규칙

- 식물원 컨셉의 초록 계열. 기념품숍은 숲 초록, 체험장은 온실 청록으로 매장을 구분합니다.
- 색만으로 뜻을 전하지 않습니다. 차이는 항상 `3 부족` / `2 더 많음` / `딱 맞아요`처럼 글자와 함께 보여 줍니다.
- 누르는 곳은 최소 44px, 숫자 입력칸은 54px 높이로 장갑을 끼고도 누를 수 있게 했습니다.
- 재고조사 화면의 화분은 센 품목 비율에 따라 씨앗 → 새싹 → 잎 → 꽃으로 자랍니다.

## 개발 메모

- 저장/불러오기는 `js/storage.js`에만 있습니다. 서버 저장소(Supabase 등)로 바꿀 때는 `init / getAll / put / putMany / remove / exportAll / importAll / clearAll`을 같은 모양으로 다시 구현하면 됩니다.
- IndexedDB를 쓸 수 없는 환경에서는 localStorage로 자동 대체합니다.
